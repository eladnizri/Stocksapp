# התראות מחיר לטלפון

האפליקציה שומרת התראות במכשיר בלבד, ולכן היא יכולה לבדוק אותן רק כשהיא
פתוחה. כדי שהתראה תגיע גם כשהאפליקציה סגורה, אותן בדיקות רצות על שרת ושולחות
התראה דרך [ntfy](https://ntfy.sh).

> **מי שולח את ההתראות.** `.github/workflows/alerts.yml` — אבל מי שמפעיל
> אותו הוא טריגר חיצוני, לא התזמון של GitHub. ראה
> [`docs/scheduling.md`](scheduling.md).
>
> `worker/quotes.js` יודע להריץ את אותן בדיקות בדיוק על Cloudflare, ואז
> מגדירים `ALERTS_OWNER` = `cloudflare` (ב־`Settings` → `Secrets and
> variables` → `Actions` → `Variables`). עד שזה מוגדר, GitHub שולח וה-Worker
> לא נוגע בכלום — אין מצב ביניים שבו אף אחד לא שולח, ואין מצב שבו שניהם
> שולחים.
>
> **סייג שהתגלה מאוחר:** התוכנית החינמית של Cloudflare נותנת **10ms CPU
> בלבד** לכל ריצת cron. המתנה לרשת לא נספרת, אבל פענוח ~20 תשובות מחיר
> ושלושה דפי לוח דוחות כן, וזה עלול לחרוג — ואז הריצה מתה בשקט. צריך למדוד
> את זה לפני שמעבירים בעלות ל-Cloudflare.

> **המסמך הזה מתאר את ההתראות שלך.** הבודק רץ היום פעם אחת לכל אדם: אתה
> מכאן, וכל מי שהאפליקציה שותפה איתו דרך `data/friends.json`. איך מחברים
> מישהו, ולמה זה עובד כך — [`docs/sharing.md`](sharing.md).

## הקמה — פעם אחת

### 1. התקן את אפליקציית ntfy

App Store → **ntfy**. חינם.

### 2. בחר שם topic

ה־topic הוא **הסוד היחיד** במערכת: כל מי שיודע אותו יכול לקרוא את ההתראות
שלך וגם לשלוח אליך התראות משלו. לכן שם ארוך ואקראי, לא `stocks` ולא השם שלך.

```bash
# ייצור שם אקראי
python3 -c "import secrets; print('stocks-' + secrets.token_hex(12))"
```

### 3. הירשם ל־topic באפליקציה

באפליקציית ntfy: **+** → הדבק את שם ה־topic → Subscribe.

### 4. שמור את ה־topic כסוד ב־GitHub

`Settings` → `Secrets and variables` → `Actions` → `New repository secret`

| | |
|---|---|
| Name | `NTFY_TOPIC` |
| Secret | שם ה־topic שיצרת |

> אל תשים את ה־topic בקוד ואל תעשה לו commit. הוא ציבורי ברגע שהוא ב־repo.

### 5. חבר את האפליקציה ל־GitHub

כדי שההתראות ייכתבו לבד, האפליקציה צריכה טוקן משלך. הוא נשמר **במכשיר
שלך בלבד** — לא בקוד ולא ב־repo.

1. [צור טוקן](https://github.com/settings/personal-access-tokens/new)
2. **Repository access** → `Only select repositories` → **Stocksapp**
3. **Permissions** → Repository permissions → **Contents: Read and write**
4. Generate token, והעתק אותו
5. באפליקציה: **הגדרות** → **סנכרון התראות** → הדבק → **חבר**

מכאן כל הוספה או מחיקה של התראה נכתבת ל־`data/alerts.json` לבד, בלי
שתיגע בזה שוב.

> הטוקן מוגבל ל־repo הזה ולקבצים בלבד. במקרה הגרוע שמישהו משיג אותו הוא
> יכול לערוך קבצים כאן — לא בחשבון שלך ולא ב־repos אחרים. אפשר לבטל אותו
> בכל רגע מ־GitHub.

**לא רוצה טוקן?** באותו מסך יש גם **העתק** + **פתח ב־GitHub** — אותה
תוצאה, אבל צריך לחזור על זה בכל שינוי ברשימה.

## בדיקה

`Actions` → `Check price alerts` → `Run workflow`.

סמן **dry run** כדי לראות מה היה נשלח בלי לשלוח באמת. הלוג מראה את המחיר
שנמצא לכל סימבול ואת המקור שלו.

## איך זה עובד

- רץ כל 15 דקות בין 13:00 ל־21:00 UTC בימים ב׳–ו׳ — חלון שמכסה את שעות
  המסחר בארה״ב גם בשעון קיץ וגם בשעון חורף.
- **מי מפעיל את הריצה:** טריגר חיצוני (cron-job.org), לא התזמון הפנימי של
  GitHub — שהוכח כאן כלא אמין ושתק פעמיים לשעות ארוכות בלי שום שגיאה.
  ההקמה מתוארת ב־[`docs/scheduling.md`](scheduling.md). התזמון של GitHub
  נשאר דלוק כגיבוי חינמי; ריצה כפולה לא מזיקה.
- כל התראה נשלחת **פעם אחת**. היא נדרכת מחדש רק אחרי שהמחיר חוזר לצד השני
  של הסף ביותר מ־1%, כדי שמחיר שיושב בדיוק על הקו לא ישלח התראה כל רבע שעה.
- המצב נשמר ב־`data/alert_state.json` ונדחף חזרה ל־repo רק כשהוא באמת משתנה.
- מחיקת התראה מ־`alerts.json` מנקה גם את המצב שלה.

## מגבלות שכדאי להכיר

- **ריצות מתוזמנות ב־GitHub Actions נדחות בעומס, ולפעמים לא קורות בכלל.**
  עיכוב של 10–30 דקות שכיח, וכאן נמדדו גם פערים של שעות ושל ימים. זה מה
  שהוביל לטריגר החיצוני. גם איתו, זה מתאים ל"תעדכן אותי כש־NVDA יורדת
  מתחת ל־180", לא למסחר תוך־יומי.
- **תוכן ההתראה לא מוצפן.** מי שיודע את ה־topic רואה אותו. אל תשים שם מידע
  שלא היית שם בהודעה גלויה.
- אם ציטוט חי לא זמין, הסקריפט נופל חזרה למחיר הסגירה האחרון ו**אומר זאת
  בגוף ההתראה** — כדי שלא תתבלבל בין מחיר של אתמול למחיר עכשיו.
- ריצות מתוזמנות ב־repo ציבורי מושבתות אוטומטית אחרי 60 יום ללא פעילות.
  הסריקה הלילית עושה commit בכל לילה, אז זה לא אמור לקרות כאן.

## מה עוד נשלח, מלבד התראות מחיר

- **קפיצה של 3% ומעלה** במניה שברשימת המעקב, פעם אחת ביום למניה. הסף
  נקבע ב־`MOVE_PCT` בתוך `scripts/check_alerts.py`.
- **סיכום יומי ב־17:00** (שעון ישראל, מתוקן אוטומטית לשעון קיץ/חורף):
  הרווח או ההפסד בכל עסקה פתוחה, הסך הכולל, ותנועת S&P ונאסד״ק. נשלח
  פעם אחת ביום, מהריצה הראשונה שנופלת בתוך השעה הזו.
- **דוח רבעוני מתקרב**, לכל מניה שיש בה עסקה פתוחה או שנמצאת ברשימת
  המעקב: התראה אחת כש־Nasdaq מפרסם תאריך דוח בטווח של יומיים קדימה
  (היום/מחר/מחרתיים), כולל אם ידוע — לפני הפתיחה או אחרי הנעילה, ותחזית
  EPS. נשלח פעם אחת לכל דוח, לא נחזר על עצמו ככל שהתאריך מתקרב. המקור הוא
  `api.nasdaq.com/api/calendar/earnings` — אותו endpoint שכבר משמש את
  הסריקה הלילית, רק בטווח של שלושה ימים במקום שמונים.

שלושתם רוכבים על אותה ריצה של בדיקת ההתראות ולא על תזמון נפרד — תזמון נוסף
הוא עוד דבר שיכול להפסיק לירות בלי להודיע, כפי שכבר קרה כאן.

## פורמט הקובץ

```json
{
  "alerts": [
    { "s": "NVDA", "d": "above", "p": 200 },
    { "s": "AAPL", "d": "below", "p": 180 }
  ],
  "watch": ["SOFI", "HOOD"],
  "positions": [
    { "s": "NVDA", "entry": 200, "qty": 100, "stop": 190, "target": 230 }
  ]
}
```

`s` סימבול · `d` הכיוון, `above` או `below` · `p` המחיר בדולרים.
שורות לא תקינות נזרקות בשקט, כך ששגיאת הקלדה באחת לא מפילה את השאר.

`watch` ו־`positions` נכתבים על ידי האפליקציה בכיוון אחד בלבד — הטלפון
נשאר הבעלים של רשימת המעקב ושל העסקאות, והשרת קורא אותם רק כדי לדעת אילו
מניות לתמחר ומה לכתוב בסיכום היומי. המחירים האלה נכתבים ל־`data/tickers.json`,
וזה מה שהאפליקציה קוראת — כך שגם רשימת המעקב כבר לא תלויה בפרוקסי חיצוני.
